# ТЗ: приложение «Мудрая йога» (рабочее название)

Версия 0.1 · 23.10.2026

Нативное Android-приложение для практики Сурья Намаскар и Чандра Намаскар как воркаута. Цель практики — измеримо снизить «возраст движения», улучшить подвижность суставов, тонус и форму тела. Методическая основа — принципы омнио-тренинга (А. Сидерский): у асаны три фазы (вход, фиксация, выход), дыхание жёстко согласовано с движением, сложность растёт через дополнительные элементы и режимы выполнения.

Выпускаем две сборки из одного кода: **Google Play** и **RuStore**.

Каждое из них можно поменять. Сейчас ТЗ написано исходя из них.

| # | Допущение | Почему |

## 2. Объём MVP

Полный перечень функций с приоритетами — в документе «Сурья — карта функций». Ниже то, что входит в первый релиз.

**Контент**
- Сурья Намаскар (Солнечное кольцо): основная последовательность + первый комплекс дополнительных элементов.
- Чандра Намаскар (Лунное кольцо): основная последовательность.
- Связка Сурья → Чандра без стандартного выхода и входа (правило стыковки из методики).
- Короткие сессии: «Утро за 10 минут», «Перед сном» (подмножество поз).
- Один режим выполнения: «Лестница в небо» (статичные фиксации, чёткие переходы).

**Функции**
1. Онбординг: цели, зоны тела, ограничения и травмы, частота занятий.
2. Тест «возраст движения»: 5 тестов, итоговый возраст, повтор раз в 14 дней.
3. План «Путь 8 недель»: дни Сурьи, Чандры, отдыха и теста.
4. Главная: карточка «Сегодня», путь, сеты, челлендж «108 кругов».
5. Карточка сессии: круги, опора (ладони / пальцы / кулаки), слоты усложнений, оценка нагрузки на запястья.
6. Плеер:
   - векторная модель (женщина / мужчина) или видео инструктора, на выбор;
   - дыхательное кольцо, подсветка живота и груди;
   - голос инструктора, привязанный к фазам; музыка;
   - скорость 0,75× / 1× / 1,25×;
   - «металлическая собака»;
   - промежуточное расслабление (шавасана с таймером).
7. Вывод на ТВ: второй экран через Miracast, HDMI или повтор экрана (Presentation API); телефон работает как пульт.
8. Финиш: итоги, вопрос «легко / в самый раз / тяжело», проблемные зоны, план следующей сессии.
9. Прогресс: возраст движения (график), календарь, серии, круги, минуты, вес и талия.
10. Напоминания: время суток, дни недели, частота.
11. Оплата: месяц, год, «навсегда»; пробный период 7 дней; напоминание за 2 дня до списания; отмена в два нажатия (ведёт в управление подписками магазина).
12. Офлайн: весь базовый контент в APK, видео докачивается и хранится локально.
13. Экспорт и импорт прогресса в файл (защита от потери данных до появления облака).

**Не входит в MVP:** аккаунты, облако, Google Cast receiver, часы и Health Connect, сообщество, женский режим цикла, режим со стулом, режимы «Воды великой реки» и «Скользящее пламя», старт-сет и стоп-сет, английский голос.

## 3. Две сборки: Google Play и RuStore

Один код, два product flavor в измерении `store`. Всё, что зависит от магазина, спрятано за интерфейсами в модуле `core`. Каждая сборка подставляет свою реализацию.

| Что | `google` | `rustore` |
|---|---|---|
| Оплата | Google Play Billing Library | RuStore Pay SDK (BillingClient) |
| Проверка покупки | Локально + (v1) серверная проверка | Локально + (v1) серверная проверка |
| Обновления | In-App Updates (Play Core) | RuStore Update SDK |
| Оценка в магазине | In-App Review (Play Core) | RuStore Review SDK |
| Push (v1) | Firebase Cloud Messaging | RuStore Push SDK |
| Аналитика и краши | AppMetrica | AppMetrica |
| Google Cast (v1) | да | только если на устройстве есть Google Play Services |
| Языки страницы в магазине | en, ru | ru |
| `applicationId` | `ru.mudrya.yoga` | `ru.mudrya.yoga` (один ID, разные магазины) |

Напоминания работают локально в обеих сборках (WorkManager + AlarmManager), push для них не нужен.

Интерфейсы в `core`:

```kotlin
interface BillingGateway {
    val entitlement: StateFlow<Entitlement>   // Free | Trial(until) | Premium(until?) | Lifetime
    suspend fun products(): List<ProductOffer>
    suspend fun purchase(activity: Activity, productId: String): PurchaseResult
    suspend fun restore(): Entitlement
    fun manageSubscriptionsIntent(): Intent
}
interface StoreServices {
    fun requestReview(activity: Activity)
    fun checkForUpdate(activity: Activity)
}
```

**Тарифы (ID одинаковые в обоих магазинах):**
- `premium_monthly` — подписка на месяц, пробный период 7 дней;
- `premium_yearly` — подписка на год, пробный период 7 дней;
- `premium_lifetime` — разовая покупка.

Цены — открытый вопрос (раздел 12).

**Честная оплата (обязательные правила):**
- Экран тарифа показывает цену, период и дату первого списания до нажатия «Оплатить».
- При старте пробного периода ставится локальное уведомление на T−48 ч до списания.
- В профиле есть кнопка «Отменить подписку», которая за одно нажатие открывает управление подписками магазина.
- Во время тренировки никогда не показываются окна продажи.
- Бесплатное ядро (базовая Сурья Намаскар, первый тест, прогресс) не урезается в обновлениях.

## 4. Архитектура

**Стек:** Kotlin 2.x, Jetpack Compose (Material 3), Coroutines/Flow, Hilt, Room, DataStore, Navigation Compose, Media3 ExoPlayer, WorkManager, kotlinx.serialization.

**Модули:**

```
:app                  — точка входа, навигация, DI, flavor-специфичные реализации
:core:model           — доменные типы (Asana, Pose, Sequence, Session...) — чистый Kotlin
:core:engine          — движок последовательностей, дыхания, подстройки — чистый Kotlin
:core:data            — Room, DataStore, репозитории, загрузка каталога из assets
:core:ui              — тема, компоненты, дыхательное кольцо
:feature:figure       — векторная модель и анимация (Canvas)
:feature:onboarding, :feature:home, :feature:session, :feature:player,
:feature:finish, :feature:progress, :feature:paywall, :feature:settings
```

`:core:model` и `:core:engine` не зависят от Android. Это позволяет гонять всю логику обычными JVM-тестами за секунды.

**Паттерн:** MVVM + однонаправленный поток данных. ViewModel отдаёт `StateFlow<UiState>` и принимает `UiEvent`.

## 5. Модель данных

### 5.1. Каталог асан (assets/catalog/*.json)

```json
{
  "id": "adho_mukha_deep",
  "names": { "ru": "Глубокий упор-горка", "en": "Deep downward dog" },
  "sanskrit": "Adho Mukha Svanasana",
  "family": "upor_gorka",
  "level": 0,
  "side": "none",
  "supports": ["palms", "fingers", "fists"],
  "load": { "wrists": 3, "shoulders": 2, "lumbar": 1, "neck": 1, "knees": 0 },
  "contraindications": ["wrist_injury_acute", "glaucoma"],
  "inversion": false,
  "cues": { "ru": ["Вес на ноги, пятки к полу", "Шея свободна"] },
  "pose": { "T": 304, "N": 300, "UA": 304, "FA": 304, "TH": 250, "SH": 250, "FT": 358 },
  "video": { "enter": "v/adho_mukha_deep_enter.mp4", "hold": "v/adho_mukha_deep_hold.mp4" }
}
```

- `pose` — углы суставов для векторной модели (градусы, 0° — вправо, 90° — вверх, вид сбоку).
- `load` — нагрузка на суставы от 0 до 3. По ней движок оценивает суммарную нагрузку и учитывает травмы.
- `side`: `none` | `left` | `right`. У зеркальных асан две записи со ссылкой `mirrorOf`.

### 5.2. Последовательности (assets/sequences/*.json)

Последовательность — это список блоков. Блок — это список шагов или ссылка на другой блок.

```json
{
  "id": "surya",
  "names": { "ru": "Сурья Намаскар" },
  "blocks": [
    { "ref": "standard_entry" },
    { "ref": "vinyasa" },
    { "ref": "inner_ring_wide_step", "side": "right",
      "slots": [ { "id": "sk_extra_1", "after": "vinyasa", "before": "wide_step_inhale" } ] },
    { "ref": "three_point_vinyasa", "side": "right" },
    { "ref": "vinyasa" },
    { "ref": "inner_ring_wide_step", "side": "left" },
    { "ref": "three_point_vinyasa", "side": "left" },
    { "ref": "vinyasa" },
    { "ref": "standard_exit" }
  ],
  "joins": { "chandra": { "skip": ["standard_exit"], "nextSkip": ["standard_entry"] } }
}
```

Шаг:

```json
{ "asana": "chaturanga", "enter": "exhale", "hold": ["inhale", "exhale", "inhale"], "extraCycles": true }
```

### 5.3. Пользовательские данные (Room)

| Таблица | Поля |
|---|---|
| `profile` | цели, зоны, травмы, пол модели, уровень, режим, опора по умолчанию |
| `plan_day` | дата, тип (surya / chandra / rest / test), статус |
| `session_log` | дата, последовательность, круги, длительность, опора, слоты, средний темп дыхания, оценка (easy / ok / hard), проблемные зоны |

## 6. Движок

### 6.1. Сборка сессии

`SessionBuilder.build(sequence, rounds, support, slots, profile) → Session`

1. Разворачивает блоки в плоский список шагов, отражает стороны.
2. Вставляет дополнительные элементы в разрешённые слоты.
3. Подставляет вариант опоры (ладони → пальцы → кулаки) там, где он задан.
4. Применяет ограничения профиля:
   - убирает перевёрнутые позы при травме шеи;
   - снижает нагрузку на запястья (кулаки, меньше поз в упоре);
   - смягчает прогибы при проблемах с поясницей.
5. Проверяет **граф переходов**: у каждой пары соседних шагов должен быть допустимый переход. Если перехода нет, сборка падает с ошибкой (ловится тестами на весь каталог).
6. Повторяет круг `rounds` раз; между некоторыми кругами вставляет промежуточное расслабление (настраивается).

### 6.2. Тайминг дыхания

Целевой ритм по методике — 3–4 дыхательных цикла в минуту (вдох и выдох по 7–9 с). Новичку это недоступно, поэтому темп адаптивный:

- старт: фаза = 4 с (настраивается 2–10 с);
- если пользователь 3 сессии подряд отвечает «легко» и не включал «металлическую собаку», фаза +0,5 с;
- если отвечает «тяжело», фаза −0,5 с, но не меньше 3 с.

Фазы шага: `ENTER(exhale)` → `HOLD(inhale, exhale, inhale)` → дальше `ENTER` следующего шага. Поле `extraCycles` разрешает добавить циклы удержания кнопкой «ещё дыхание».

Задержек дыхания в MVP нет (в нулевом цикле методики их тоже нет).

### 6.3. Подстройка после сессии (Finish)

| Ответ | Изменение следующей сессии |
|---|---|
| Легко | +2 круга (до лимита уровня) или открыть следующий слот; опора кулаки → ладони → пальцы |
| В самый раз | без изменений; +1 круг каждые 3 сессии |
| Тяжело | −2 круга (минимум 2); больше расслаблений; слоты скрыты |

Отмеченные проблемные зоны снижают долю поз с высокой нагрузкой на эту зону на 30% в течение 7 дней.

### 6.4. Возраст движения

5 тестов: сесть и встать с пола без опоры (шкала 0–10), наклон вперёд стоя (см до пола), баланс на одной ноге с закрытыми глазами (с), отжимания подряд, восстановление пульса через 60 с после 6 кругов.

Итоговый возраст = паспортный возраст + сумма поправок по каждому тесту относительно возрастной нормы. Нормы и веса берутся из опубликованных исследований (подбор источников — этап 1). Формула лежит в `:core:engine` и покрыта тестами на граничных значениях. На экране обязательна пометка, что это оценка, а не медицинский показатель.

## 7. Экраны

Прототип: восемь экранов в документе-холсте «Сурья — прототип приложения». Список экранов MVP:

1. Splash → онбординг (5 шагов) → тест → результат теста.
2. Главная (вкладки: Практика · Сеты · Прогресс · Профиль).
3. Сеты: каталог сетов и коротких сессий.
4. Карточка сессии.
5. Плеер (портрет), плеер (альбом и ТВ).
6. Промежуточное расслабление.
7. Финиш.
8. Прогресс; повторный тест.
9. Каталог асан → карточка асаны.
10. Профиль и настройки: модель Ж/М, голос, музыка, скорость, напоминания, травмы, экспорт / импорт, подписка.
11. Пейвол.

**Плеер.** Модель рисуется на Compose Canvas. Сегменты тела — сужающиеся капсулы, позы интерполируются по углам суставов (кратчайший путь по окружности, easeInOut). Частота кадров 60 fps; вычисления позы выполняются вне композиции.

**Видео.** Для каждой асаны два клипа: «вход» и «петля удержания». Петля повторяется столько раз, сколько дыхательных циклов в удержании. Голос — отдельная аудиодорожка, привязанная к фазам.

## 8. Вывод на ТВ

**MVP — Presentation API.** Если к телефону подключён второй экран (Miracast, повтор экрана, HDMI через USB-C, «Трансляция экрана» на Chromecast), приложение через `DisplayManager` находит его и показывает на ТВ отдельный макет плеера: крупная модель или видео, кольцо дыхания, название позы. На телефоне в это время пульт: пауза, вперёд / назад, громкость, «металлическая собака». Работает в обеих сборках, SDK не нужен.

**v1 — Google Cast** (только сборка `google` и устройства с Google Play Services): Custom Web Receiver — веб-страница на ТВ, которая рисует модель по состоянию сессии из сообщений по Cast-каналу. Видео идёт через Media3 Cast.

**Звук.** Bluetooth используется только для звука: голос и музыка уходят в подключённую колонку или наушники через стандартный аудиовыход. Изображение по Bluetooth не передаётся.

## 9. Нефункциональные требования

- **Офлайн:** всё, кроме загрузки видео и покупки, работает без сети.
- **Производительность:** холодный старт меньше 2 с на среднем устройстве, плеер стабильно 60 fps.
- **Размер:** APK без видео меньше 25 МБ; видео докачивается по сетам.
- **Экран во время сессии не гаснет**, звук продолжает идти при блокировке (foreground service с уведомлением-пультом).
- **Доступность:** контраст 4.5:1, кнопки от 48 dp, TalkBack озвучивает фазу и позу, крупный шрифт не ломает вёрстку.
- **Приватность:** данные о здоровье (травмы, вес, тесты) хранятся только на устройстве; аналитика обезличенная, без этих полей. Политика конфиденциальности на ru и en. Анкета Data Safety в Google Play и раздел о данных в RuStore.
- **Медицинские формулировки:** никаких обещаний лечения или похудения за N дней; дисклеймер в онбординге и на странице в магазине.

## 10. Тестирование

| Уровень | Чем | Что проверяем |
|---|---|---|
| Unit (JVM) | JUnit 5, Kotest assertions, Turbine | Движок: развёртка блоков, зеркалирование, слоты, опоры, граф переходов по всему каталогу, тайминг дыхания, подстройка, формула возраста движения, ограничения по травмам. ViewModel-ы. Маппинг покупок в `Entitlement` |
| Данные | Room in-memory + MigrationTestHelper | Все миграции, экспорт / импорт |
| Скриншоты | Roborazzi (JVM, без эмулятора) | Все экраны в светлой и тёмной теме, ru / en, крупный шрифт, обе модели |
| UI-сценарии | Compose UI Test на эмуляторе в CI | Онбординг → тест → первая сессия → финиш; пауза и возобновление; пейвол |
| Оплата | Fake-реализации `BillingGateway` + тестовые покупки магазинов | Пробный период, отмена, восстановление, «навсегда» |
| Ручной чек-лист | Перед каждым релизом, ~20 минут | Реальный телефон, ТВ через Miracast / HDMI, Bluetooth-колонка, блокировка экрана, реальная покупка |

Минимальное покрытие `:core:engine` — 90% строк.

**CI (GitHub Actions):** на каждый push и pull request — lint, detekt, unit-тесты, Roborazzi-проверка, сборка `googleDebug` и `rustoreDebug`. Ночной прогон: UI-тесты на эмуляторе. По тегу `v*` — подписанные `googleRelease` (AAB) и `rustoreRelease` (APK) как артефакты сборки. Ключ подписи хранится в GitHub Secrets.

## 12. Открытые вопросы

1. Название и иконка приложения.
2. Цены: месяц, год, «навсегда» — в рублях для RuStore и в долларах для Google Play.
3. Нужен ли английский голос до релиза в Google Play или достаточно английских субтитров.
4. Видео: когда будут съёмки и в каком объёме для MVP (только Сурья + Чандра — примерно 60 клипов).
5. Иллюстрации моделей: остаёмся на собственной векторной модели или заказываем художника.
6. На кого оформляется аккаунт разработчика (самозанятость или ИП для выплат RuStore; Google Play — частное лицо или организация).
7. Кто вычитывает описания и противопоказания (инструктор, врач ЛФК).
